# Status of the former scope limits

The earlier paragraph beginning “No customer account system” describes the first storefront version. It is obsolete for the implementation introduced in commit `baa59f5` on `work`. The table below distinguishes implemented code from provider-backed launch acceptance; it does not imply that optional services are already enabled.

| Former limitation                        | Current implementation                                                                                                         | Activation or remaining boundary                                                                                                                                                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| No customer accounts                     | `/account`: email-link sign-in, address book, order history, export and server-side wishlist                                   | Configure verified transactional email and account authentication.                                                                                                                                     |
| No refunds portal                        | `/returns` customer requests; Operations → Returns / Refunds for review, partial/full refunds and separate physical restocking | Card refunds use Stripe jobs/events. M-Pesa refunds require two named operators and a real external refund reference; no automated B2C reversal call.                                                  |
| No card disputes automation              | Signed dispute events record status and automatically hold fulfilment                                                          | Evidence submission, representment, arbitration and settlement reconciliation remain in the provider dashboard.                                                                                        |
| No product variants                      | Independent SKU prices/stock, parent SKU, variant attributes and shopper selection                                             | Populate approved real SKUs and variant data.                                                                                                                                                          |
| No search index                          | MongoDB full-text index, bounded search/filter/sort APIs and pagination                                                        | Run `npm run db:prepare`. Typo-tolerant/semantic search is outside the current implementation.                                                                                                         |
| No media upload service                  | Operations → Media; bounded raster uploads sanitized to WebP; GridFS or S3-compatible storage                                  | Configure storage permissions/backups and use approved licensed images.                                                                                                                                |
| No coupons                               | Operations → Promotions; expiry, usage limits, transactional reservation/redemption and exact minor-unit discounts             | Create approved offers and test their commercial rules.                                                                                                                                                |
| No reviews                               | Verified-purchaser submissions and staff moderation; only approved reviews displayed                                           | Establish moderation and customer-support procedures.                                                                                                                                                  |
| No M-Pesa jurisdictional tax integration | Optional Stripe Tax quotes for M-Pesa, expiring totals, tax transaction/reversal jobs; approved flat-rate alternative          | Requires Stripe Tax eligibility/registrations and rounding approval. Partial-refund adjustments can require manual tax review. This is provider integration, not an independent global tax-law engine. |
| No carrier integration                   | Shippo operator rates, label purchase and tracking polling                                                                     | Requires provider credentials/carrier acceptance. Checkout shipping remains approved fixed per-order rates; international customs arrangements are merchant-owned.                                     |
| No multi-warehouse stock                 | Warehouse balances, transactional allocation, audited transfers/adjustments and idempotent restocking                          | Configure actual dispatch locations and reconcile physical stock.                                                                                                                                      |
| No multi-operator audit UI               | Named owner/manager/support/warehouse/finance roles, permission-filtered Operations panel and audit history                    | Provision individual verified staff accounts and operational responsibilities.                                                                                                                         |
| No in-app admin MFA                      | Encrypted TOTP enrollment, replay protection, recovery codes and fresh-MFA gates for sensitive actions                         | Set the encryption secret, enroll staff and disable bootstrap before launch.                                                                                                                           |
| Only USD/KES, no conversion              | Currency list is centrally configurable; ISO decimal handling and optional OpenExchangeRates conversion with stale-rate checks | Leron intentionally offers KES/USD today. FX is disabled by default. Additional currencies require prices or current FX, payment-provider support, tax and shipping acceptance.                        |
| Admin shows only 100 orders              | Cursor-based order API and Load more UI, 50 records per page                                                                   | The 50-record batch bounds each request; it is not a total-history limit.                                                                                                                              |

## Where to configure and operate

- Public brand, contacts, theme, currencies, feature flags and draft policies: `src/config/site.ts`.
- Runtime credential and service settings: `.env.example` and the deployment secret manager.
- Staff catalog/orders: `/admin`; operational queues: `/admin/operations`.
- Setup, acceptance and recovery: [production-readiness.md](production-readiness.md).
- Tests and measured limits: [validation.md](validation.md).
- Broader architecture and explicit boundaries: [architecture.md](architecture.md).

Live trading remains disabled. The configured MongoDB hostname failed DNS resolution during validation, and payment/email/shipping/FX services still need the acceptance documented in the launch guide. Do not replace the old paragraph with an unconditional “all features live” claim.
